# LAS Recomp on iOS (sideloaded)

**Status: untested.** Written and reviewed off-device; nothing here has been compiled for iOS or run on an iPhone yet.
Expect to fix compile errors on first build (SDL hint names in `runtime/nvn/metal.m` are the likeliest).

## How it differs from desktop
- No JIT, no spawning processes, no loading locally built code. So the game's code runs in the **interpreter tier**
  (`runtime/interp*.c`): it reads the AArch64 instructions out of your `main` / `sdk` files at run time, decodes each one
  the first time it executes and runs the decoded form. **No `make gen`, no Mac-built library, no build step on the phone:**
  the app and your game files are all that is needed.
- It does what the generated code does: the same host replacements (`tools/patches.py` -> `runtime/interp_patches.c`,
  generated by `tools/gen_interp_patches.py`), the same randomizer patch sites, the same HLE/override mechanism, the same
  FP/SIMD semantics (`runtime/simd*.h`).
- Optional speed-up: a `lasgame.dylib` built on a Mac (`make ios-gen`) next to the app (`Frameworks/`) is used instead of
  the interpreter when present (compiled code is several times faster).
- Touch controls (`runtime/ui/touch_pad.mm`): left stick, A/B/X/Y, L/R, +/-, and a menu button.
- Data lives in the app's Documents folder (visible in Files > LAS Recomp).

## Build (on a Mac with Xcode)
1. `make ios-deps`        # static SDL3 + FFmpeg for arm64 iOS -> build/ios-deps
2. `make ios`             # builds the app and `build/ios/LAS Recomp.ipa`
   (override with `IOS_MIN=16.0`, `BUNDLE_ID=...`)
3. (optional) `make ios-gen` first, with your game files in extracted/, to bundle the compiled game code as well.

If you change `tools/patches.py` or `tools/rando/patch_variants.json`, run `python3 tools/gen_interp_patches.py` to
update `runtime/interp_patches.c`.

## Testing the interpreter (any machine with clang + lld, no game needed)
- `python3 tools/test_interp.py --only all --words 50000` : every instruction word, one at a time, against the lifter's
  C on random state (registers, flags, V registers, memory). 0 mismatches at the time of writing.
- `tools/test_interp_e2e.sh [-O2|-O3|-Os]` : AArch64 programs (integer code, FP, NEON, AES, SHA-256, CRC32, atomics,
  jump tables, function pointers, recursion) compiled with clang and run by the interpreter, each checking itself.
  Prints speed too (about 0.5-0.7 G guest instructions/s on a desktop x86 core).
- `LARECOMP_INTERP=1` forces the interpreter on desktop builds, to try it on the real game.

## Install
Sideload the IPA with AltStore / SideStore / Sideloadly. The IPA is only ad-hoc signed to carry
`tools/ios/entitlements.plist`; your sideloader re-signs it.

The game reserves a ~12.5 GB virtual window, which needs the **extended-virtual-addressing** and
**increased-memory-limit** entitlements. A free Apple ID may not grant them; if the app shows the "could not reserve
guest memory" box, that is why (a paid developer account, or a shifted/smaller window, is the fix).
Needs a device with 6 GB+ RAM.

## First run
Copy `exefs` and `romfs` (and optionally `fonts/`) into Files > LAS Recomp > Import, then open the app.

## Not done / unknown
- **Not run on a device, and not run against the real game** (no game files were available where this was written). The
  interpreter is verified against the lifter and on test programs, not on Link's Awakening itself.
- **Speed is unknown.** The interpreter does a few hundred million guest instructions per second on a desktop core;
  a phone is slower, and the game needs a lot per frame. Expect the possibility of well under 30 fps. Frame pacing
  (`runtime/hle/framepace.c`) keeps game time correct when slow, but it will look slow. Profile with `LARECOMP_INTERP=1`
  on a desktop first.
- First run after a seed change / reboot decodes code again (lazy, spread over the first seconds of play).
- Unicorn removal from `tools/gen.py` (only matters if gen is to run somewhere without a JIT).
- Nintendo shared fonts: falls back to the bundled Baloo2 (Latin only) unless you provide `fonts/`.
